How the system holds together

One source of truth
Core Tokens owns every colour, font, spacing step, radius and pictogram. The other four documents state what they inherit and never redefine it locally. When a token changes, it changes in one file.
Two voices, one palette
Product and website run on Inter with no gold text highlight. Marketing carries the Barlow display voice and the single-highlight rule. Same tokens, different register — and each document says which it is.
Components travel
The workflow strip in Marketing is the hero sequence on the website. The status scale in Core Tokens drives severity, board ageing and agent state. Nothing is drawn twice.
Coverage. Every surface RTPM ships is specified: the mark, the product, mobile, the agent, the marketing templates and the website. A future module is assembled from patterns already in the system — it should not require a new one. If it does, the gap belongs in Core Tokens first.
What is left

The system is specified end to end. What remains is not design work.

01 · Sign-off
Each document ends with three decisions. Until you answer them, components stay at Candidate rather than Locked. They are listed against each document above.

03 · Build rtpm.dk
The architecture is specified but no page is built. That is the natural next piece of work once the website decisions are settled.
