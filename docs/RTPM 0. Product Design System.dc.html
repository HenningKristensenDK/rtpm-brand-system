RTPM Brand System v4 · Product design language · 2026.08.04

RTPM Product Design System

The visual operating system for a capital project control platform. Command Layer structure, Instrument Panel discipline, Institutional Ledger proof. Built on the Step 1 foundation — no tokens are introduced here that were not locked there.

Master · Command Layer Discipline · Instrument Panel Trust · Institutional Ledger
Inherited and unchanged from RTPM 1. Core Tokens: all colours, fonts, spacing and radius. No new token is introduced in this file.
Every number has an owner
No figure appears without the person and organisation accountable for it. A KPI with no owner is decoration.
State before styling
Where a record sits in its workflow is the first thing readable on every surface. Colour supports it, never carries it alone.
Nothing changes silently
Every state change writes a visible, attributed, timestamped line. The audit trail is a first-class component, not a log tab.
Calm at density
These screens hold hundreds of rows. Quiet neutrals, hairline rules, one accent. Emphasis is earned by exception only.
01

App shell

Left navigation · Top bar · Project context · Global search · Profile
Shell container
The frame every module inherits. Built once, never per-module.
Candidate for locking
Purpose
Hold the user's place in a portfolio of large projects. At any moment the shell answers three questions without a click: which project am I in, which module am I in, and what is waiting for me.
Module icons are specified in RTPM 1. Core Tokens, section 07, and are not redefined here.
Design principles
One dark anchor only — the navy sidebar. The top bar stays light so the eye reads content, not chrome. Project context lives in the top bar because it changes; modules live in the sidebar because they do not.
Layout rules
Sidebar 232pxFixed. Collapses to 60px icon rail below 1280px. Logo once, in the sidebar header.
Top bar 56pxWhite, 1px bottom border, no shadow. Project switcher left, search centre, actions and profile right.
Content 24px gutterPage background #F7F7FB, cards white. Max content width unbounded — registers need the room.
Right dock 360pxReserved for the agent panel and record panels. Overlays content below 1440px, never squeezes a table.

Dashboard language

Executive · Project · PMO
Information priority — the four-band rule
Every dashboard reads top to bottom in the same order, whatever the role.
Candidate for locking
BAND 1
Position
Where the project stands right now. One health verdict plus 4–6 KPI cards. No charts.
BAND 2
Trajectory
Where it is heading. Milestone timeline, schedule confidence, trend against baseline.
BAND 3
Exceptions
What is wrong and who owns it. Risk matrix, critical items, overdue queues — each row names a person.
BAND 4
Recommendation
What the agent suggests doing next, always with the evidence it used and an accept/dismiss action.
Executive dashboard
Portfolio level. Read in 30 seconds, standing up, before a board call.
Candidate for locking
Purpose
Answer one question across the portfolio: which projects threaten commercial operation date or capital envelope, and is anyone already on it. No operational detail.
Layout rules
One row of portfolio KPIs, then one row per project. Project rows are ranked by exposure, never alphabetically. Maximum eight rows before pagination — an executive view that scrolls has failed.

03

Register language

Risk · Document · Correspondence · Change
Universal register anatomy
One structure. Only the columns change between modules.
Candidate for locking
Purpose
The register is the ledger. It is where a project proves what was raised, when, by whom, and what happened next. Every module's list view is the same object with a different column set, so a user who learns one has learned all of them.
Design principles
Five fixed columns in every register: ID, title, state, owner, date. Module-specific columns insert between state and owner. Rows never change background colour — state is carried by the indicator so a printed register survives greyscale.
Layout rules — five stacked zones
1 · Header
Module name, live count "20 of 20 items", view toggle, and one primary New action.
2 · Filter bar
Max six dropdowns, all defaulting to "All". Active filters become removable chips below.
3 · Summary strip
Totals, completion donut, distribution by workstream and by stakeholder. Every element filters the table.
4 · Table
Row height 44px. Sticky header. ID column monospaced tabular. Sort by one column, indicated in the header.
5 · Row action
Whole row opens the record panel. Destructive actions sit at the far right, icon only, never on hover alone.

04

Universal record

Risk · Document · Correspondence · NCR · Change · Compliance
Record detail panel
One pattern for all six record types. The single most reused screen in the platform.
Candidate for locking
Purpose
Hold everything a record needs to be defensible: what it is, where it stands, who owns it, what was agreed, and what evidence supports it. If a claim were tested, this panel is the exhibit.
Design principles
Section order never varies between record types — a user auditing a change order and an NCR reads the same shape. Types differ only in which optional blocks appear. One primary action, always top-right, always the same action: send the update that creates the record.
Layout rules — fixed section order
1 · Identity headerBack, title, record ID chip, created and last-edited stamps. Primary action right.
2 · Workflow stateFull stepper with stage owners. Always above the fold, never inside a tab.
3 · FieldsTwo columns. Status and priority first, dates second, classification third.
4 · Involved partiesResponsible and Informed, split. Role and organisation under every name.
5 · ChecklistCounted in the heading. Completed items strike through, never disappear.
6 · NotesNarrative field. Plain, wide measure, no rich formatting toolbar.
7 · AttachmentsCounted tab. Filename, revision, uploader, date — never thumbnails alone.
8 · Audit trailCloses the panel. Every entry attributed and timestamped. Read-only, always.

06

AI agent system

Governed · controlled · transparent
The agent proposes. A named human disposes.
Bounded
Every agent is scoped to a role and a data boundary, both stated in its header. No general-purpose assistant.
Sourced
Every claim cites the records it read, by ID. An answer without citations is a defect.
Held
The agent drafts and stages. It never sends, never changes a status, never closes a record on its own.
Plain
No sparkles, no glow, no typing flourish, no purple gradient. Gold hairline marks agent surfaces and nothing else does.
Agent home
The zero state front door.
Candidate
Purpose & rules
Open on a question, not a blank box. Four suggested prompts, each phrased as a real control question this role asks daily. A skip link to the dashboard is always present — an agent that cannot be bypassed is a gate, not a tool.
